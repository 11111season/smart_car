# 基于 IR 摄像头的智能车视觉识别系统技术文档

## 1. 概述

本系统运行于 Infineon TRAVEO T2G CYT4BF 双核 MCU 的 **CM7_1（camera 核）**，通过 MT9V03X IR 摄像头采集 188×120 二值化图像，对图像中的白斑（高亮区域）进行连通域提取和**软判决评分分类**，实时识别信标灯、车头（IR LED 光斑）和车尾（车身反光），并通过共享内存将结果传递给 **CM7_0（control 核）**。

### 系统架构

```
IR 摄像头 → 二值化 → BFS连通域提取 → 软判决评分 → 跨帧跟踪 → 类型判决 → 头尾配对 → 坐标变换
                                                                                 ↓
                                                                        共享内存 (vision_share_t)
                                                                                 ↓
                                                                        CM7_0 控制核
```

## 2. 图像预处理

- **分辨率**：188 × 120（`CAMERA_W × CAMERA_H`）
- **二值化阈值**：`IR_THRESHOLD = 140`，像素值 ≥ 140 置为 255（白），否则为 0（黑）
- **核心高亮阈值**：`IR_CORE_THRESHOLD = 200`，用于区分普通反光和强光源

## 3. 连通域（Blob）提取

采用 BFS（广度优先搜索）**四方向**（上下左右）扫描连通域：

| 参数 | 值 | 说明 |
|---|---|---|
| `MIN_IR_PIXEL_COUNT` | 3 | 连通域最小像素数，小于此值视为噪声 |
| `MAX_BLOBS` | 20 | 每帧最大 blob 数量 |

### Blob 数据结构

```c
typedef struct {
    uint16 cx, cy;           // 质心坐标
    uint16 width, height;    // AABB 轴对齐包围盒尺寸
    uint16 area;             // 像素面积（连通域像素总数）
    uint16 core_count;       // 核心高亮像素数（≥200）
    BlobType type;           // 最终类型
    uint16 owidth, oheight;  // 带方向的最小外接矩形尺寸
    uint8 raw_beacon_score;  // 原始信标分
    uint8 raw_head_score;    // 原始车头分
    uint8 raw_tail_score;    // 原始车尾分
    uint8 track_id;          // 跨帧跟踪 ID
    uint8 filt_beacon_score; // 滤波后信标分
    uint8 filt_head_score;   // 滤波后车头分
    uint8 filt_tail_score;   // 滤波后车尾分
} Blob;
```

## 4. 带方向最小外接矩形

基于图像二阶矩（惯性矩）计算主轴方向，是解决偏航 45° 下车尾宽高比失真问题的关键技术。

### 计算流程

1. **图像矩计算**：对连通域内所有像素计算相对于质心 `(mx, my)` 的二阶矩：
   - `Ixx = Σ(dx²)`, `Iyy = Σ(dy²)`, `Ixy = Σ(dx·dy)`
2. **主轴方向**：`θ = 0.5 × atan2(2·Ixy, Ixx - Iyy)`
3. **旋转投影**：将各像素沿主轴 `(cosθ, sinθ)` 和副轴 `(-sinθ, cosθ)` 方向投影
4. **外接矩形**：取 u/v 方向的极差作为 `owidth` 和 `oheight`

### 关键指标

- **`oratio`**：`owidth × 100 / oheight`（百分比宽高比，正方形 = 100）
- **`ord`**：`|oratio - 100|`（偏离正方形的程度，ord 越大越呈长条形）
  - 正方形小圆点：ord ≈ 0~20
  - 中等长条：ord ≈ 50~100
  - 车尾（典型）：ord ≥ 150

## 5. 软判决评分系统

每个 blob 独立计算三个通道的置信度分数（0~100），分数越高越可能是该类型。

### 5.1 信标分（Beacon Score）

适用于中等面积、接近圆形的 blob，长条形被惩罚。

| 子项 | 分值范围 | 计算方式 |
|---|---|---|
| 面积 | 0~50 | 峰值 20~50 得满分；50~100 线性下降；100~150 大幅衰减 |
| 圆度 | 0~50 | `100 - rd`，rd 为 AABB 宽高比偏离度，低圆度至少得 10 分 |
| 长条惩罚 | 衰减因子 | `ord > 50` 时信标分 × `(150 - ord) / 100`，`ord ≥ 150` 归零 |

### 5.2 车头分（Head Score）

适用于小面积（10~60px）、接近圆形的 blob，通常对应车头的 IR LED 光斑。

| 子项 | 分值范围 | 计算方式 |
|---|---|---|
| 面积 | 0~50 | 10~60 满分；60~100 线性归零；3~10 线性增加 |
| 圆度 | 0~50 | 与信标分相同的圆度评分 |

### 5.3 车尾分（Tail Score）

适用于大面积、明显长条形的 blob，通常对应车身反光区域。

| 子项 | 分值范围 | 计算方式 |
|---|---|---|
| 面积 | 0~70 | `< 100` 不得分；100~250 线性增至 70；250~500 满分；>500 衰减归零 |
| 长条偏离度 | 0~60 | `ord < 30` 不得分；30~100 线性增至 60；≥100 满分 |

### 5.4 空间邻近加分

利用车头与车尾的空间关系提升配对成功率：找到当前帧原始车尾分最高的 blob（`> 60`），对距离其曼哈顿 `< 80px` 的 blob 的车头分加 `80 - dist`（上限 +50）。

### 5.5 亮度加权

基于 `brightness = core_count × 100 / area`（核心高亮像素占比）对三类分数进行连续调制：

| 亮度范围 | 信标分 | 车尾分 | 车头分 |
|---|---|---|---|
| 高亮 100% | +50 | 0 | 0 |
| 中亮 65% | +25 | +50 | +25 |
| 低亮 0% | 0 | 0 | +50 |

- 信标分加成：`brightness × 50 / 100`
- 车尾分加成：峰值在 65%，`50 - |brightness - 65| × 50 / 35`
- 车头分加成：`(100 - brightness) × 50 / 100`（亮度越低加成越高）

## 6. 跨帧跟踪

### 匹配策略

- **最近邻匹配**：计算当前帧 blob 与上一帧 blob 之间的欧氏距离²
- **匹配阈值**：`TRACK_MATCH_MAX_DIST2 = 625`（约 25px 半径）
- **历史继承**：匹配成功则继承上一帧的 `track_id` 和三个通道的滤波分数
- **新 blob**：分配全局递增 `track_id`（从 1 开始，永不重置），用 `raw_score` 初始化 `filt_score`

### 一阶滞后滤波

```c
filt_score = 0.65 × 历史滤波分 + 0.35 × 当前原始分
```

- 历史权重 `SCORE_HISTORY_WEIGHT = 0.65`
- 当前权重 `SCORE_CURRENT_WEIGHT = 0.35`

## 7. 类型判决

### 判决流程

1. **找最高分**：从三个通道的判决分数（首帧用 raw，后续用 filt）中取最高
2. **门槛判定**：
   - 首帧（`track_id=0`）：`max ≥ 15` 且 `margin ≥ 8`
   - 匹配帧：`max ≥ 30` 且 `margin ≥ 8`
3. **历史继承**：未通过门槛但有历史记录，若历史类型与当前最高分类一致则继承，否则信任当前最高分
4. **强制车头**：有车尾且仅有一个非尾 blob 时，强制设为车头

### 去重规则

- 场上**至多一个车头和一个车尾**，取各自滤波分最高的保留
- 其余类型为 `UNKNOWN` 的 blob 全部标记为 **信标**

## 8. 信标选择策略

- **单信标**：直接取用
- **多信标**：基于上一帧历史信标位置，选择**距离最近**的一个
- **无历史**：取第一个信标

## 9. 车头尾配对与航向解算

### 配对条件

- 曼哈顿距离：`CAR_MATCH_MIN_DIST2 = 9`（3px）~ `CAR_MATCH_MAX_DIST2 = 3600`（60px）
- 取距离最远的头尾对作为最终配对

### 航向角

```c
heading = atan2(head_y - tail_y, head_x - tail_x)
```

### 一阶低通滤波

```c
filtered_cos = 0.7 × 历史cos + 0.3 × 当前cos
filtered_sin = 0.7 × 历史sin + 0.3 × 当前sin
heading_angle = atan2(filtered_sin, filtered_cos)
```

## 10. 坐标变换与误差输出

### 车体坐标系变换

将信标相对小车的图像坐标差，旋转到**车体坐标系**：

- **车头方向 = +x**，**车身右侧 = +y**
- 转换公式：
  ```
  err_x = -(dx·cosθ + dy·sinθ)
  err_y = -(-dx·sinθ + dy·cosθ)
  ```

### 误差衰减

当目标丢失时，误差值每帧乘以 `ERR_DECAY_FACTOR = 0.85`，实现平滑过渡，避免突变。

## 11. 共享内存结构（vision_share_t）

```c
typedef struct {
    uint32 frame_id;            // 帧序号
    int16 err_x, err_y;         // 信标相对小车的车体坐标系误差
    uint16 target_found;        // 同时识别到信标和小车
    int16 beacon_err_x, beacon_err_y;  // 信标相对画面中心的误差
    uint16 beacon_found;        // 信标存在标志
    int16 car_x, car_y;         // 小车中心坐标
    uint16 car_found;           // 小车存在标志
    float heading_angle;        // 滤波后航向角
} vision_share_t;
```

共享内存地址：`0x28001000`，每次更新后通过 `SCB_CleanInvalidateDCache_by_Addr` 刷新 D-Cache。

## 12. 可视化标注

| 类型 | 标注 | 颜色 |
|---|---|---|
| 信标（BEACON） | 十字（5px） | 黑色（像素值 0） |
| 车头（CAR_HEAD） | 方框 3px | 白色（像素值 255） |
| 车尾（CAR_TAIL） | 方框 5px + 十字 | 白色方框 + 黑色十字 |

## 13. 关键参数总表

| 参数 | 值 | 用途 |
|---|---|---|
| `IR_THRESHOLD` | 140 | 二值化阈值 |
| `IR_CORE_THRESHOLD` | 200 | 核心高亮阈值 |
| `MIN_IR_PIXEL_COUNT` | 3 | 连通域最小像素数 |
| `TRACK_MATCH_MAX_DIST2` | 625 | 跨帧匹配最大距离²（≈25px） |
| `SCORE_HISTORY_WEIGHT` | 0.65 | 滤波历史权重 |
| `SCORE_CURRENT_WEIGHT` | 0.35 | 滤波当前权重 |
| `SCORE_MIN_CONFIDENCE` | 30 | 匹配帧最低置信度 |
| `SCORE_MIN_MARGIN` | 8 | 判决最小 margin |
| `CAR_MATCH_MIN_DIST2` | 9 | 头尾配对最小距离²（≈3px） |
| `CAR_MATCH_MAX_DIST2` | 3600 | 头尾配对最大距离²（≈60px） |
| `HEADING_FILTER_ALPHA` | 0.7 | 航向滤波系数 |
| `ERR_DECAY_FACTOR` | 0.85 | 误差衰减系数 |

## 14. 调试接口

通过 `DEBUG_SCORES = 1` 启用串口调试输出（与 HC06 蓝牙共享 UART）：

```
frame_id,blob_num, track_id,area,brightness%,oratio,raw_b,raw_h,raw_t,filt_b,filt_h,filt_t,type, ...
```

每个 blob 输出 11 个字段，最多输出 5 个 blob，每帧一行。
