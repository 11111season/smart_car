## 四、遥控器模拟无人机 (LoRa, 2026-08-07 完成)

### 遥控器协议映射
```
协议结构 (lora3a22_uart_transfer):
  joystick[4]  摇杆轴值 (±2047量程): [0]左杆X [1]左杆Y [2]右杆X [3]右杆Y
  key[4]      按键 (按下1松开0): [0]摇杆上 [1]摇杆右 [2]副机左 [3]副机右
  switch_key[4] 拨杆开关 (默认1): [0]左拨杆1 [1]左拨杆2 [2]右拨杆1 [3]右拨杆2

小车信道映射:
  左杆X → 左右平移 (pos_error_y)
  左杆Y → 前后平移 (pos_error_x)
  右杆X → 自转 (angle_target 增量式)
  拨杆1 1→0 → 完赛 (flag=3)
```

### 遥控空闲/断连 → 惯导巡逻 (两级判"丢信标")
遥控器**开机后每50ms必发一帧(即使不操作)**, 不能只靠"收不到帧"判丢信标:
```
A. 断连: 完全收不到帧 (遥控关机) >200ms → flag=2
B. 空闲: 收到帧但摇杆全回中+无按键 >2s    → flag=2 (模拟无人机认为无信标)
两者都累加 flag2_count, ≥10 (FLAG2_DEBOUNCE) 才确认丢信标 → 触发巡逻
```
有操作 (任一摇杆离开死区80 或 按键按下) → flag=1 → 手动控制, 打断巡逻。

### 完赛触发 (拨杆1号)
```
拨杆 switch_key[0] 1→0 (边沿) + mission_armed → race_done=1 → ISR race_locked
两道保险:
  1. 首帧(sw0_prev=0xff)只记录不判定 → 上电/遥控关机读到0不会误触发
  2. 仅 mission_armed 后生效 → 记录航点阶段误碰拨杆不锁车
```

### 巡逻逻辑 (inertial_nav.c)
```
触发: 武装 + 3.5s后 + flag2_count≥10 + 未在巡逻 + 消抖结束
逻辑: 选更近航点导航 → 到达等3s → 无信标切另一航点 → 循环
打断: flag=1 (信标出现) 立即打断, 恢复手动控制
```

## 五、菜单系统 (App_Menu, 显示 + 控制逻辑)

### 架构
IPS200 2.0" SPI LCD (240×320 纵向, 横排文本) + 16×16 汉字点阵字库 (PCtoLCD2002: 阴码/逐行式/顺向/16x16/C51格式, 每字 32 字节, bit=1 画前景色)。
`App_Menu_Task()` 在 10ms 任务里轮询按键, 状态机每轮只处理当前状态; 页面切换时整页重绘, 同页按键时增量重绘两行 (空闲零 SPI 流量)。

### 按键映射 (全局)
| 按键 | 功能 |
|------|------|
| KEY_1 | 滚动高亮 / 数值递增 (封顶9 / +0.2m封顶+2.0 / 速度限幅+0.05m/s封顶0.5) |
| KEY_2 | 确认进入 / 数值确认 / 无人机起桨→起飞 |
| KEY_3 | 任意状态返回主菜单 (**不挂任何控制逻辑**, 避免与菜单冲突) |
| KEY_4 | 数值递减 (保底1 / -0.2m保底-2.0 / 速度限幅-0.05m/s保底0) / 记录页**首次按=取消闭环**, 之后开始结束记录 / 发车推进 |

**记录页按键设计**: 记录页不能用 KEY_3 退出(那是全局返回), 取消闭环改放记录页**第一次 KEY_4** (PID全关, 车可自由推动摆车头), 从第二次 KEY_4 起才正式开始记录。例: 设置 2 个航点 → 共按 5 次 KEY_4 (1 取消 + 4 记录)。

### 菜单树 (含控制逻辑)

### 运行时配置变量 (非 static, App_menu.h extern 暴露, 上电由 W25Q64 覆盖)
| 变量 | 含义 | 说明 |
|------|------|------|
| `wp_set` | 记录航点总数 | 菜单"设置航点数量"设 (1~9) = 惯导 `bcn_max`; 记录流程显示循环次数 |
| `launch_enable` | 发车区航点启用 | 1=启用 0=禁用 (默认1); 决定 `wp_max` 是否 +1 |
| `launch_off_x/y` | 发车区偏移 | int16, 单位 0.1m, 范围 ±20 (±2.0m); x 前正后负对应小车 vx, y 左正右负对应小车 vy |
| `spd_limit_x/y` | 惯导速度限幅 | uint8, 单位 0.05m/s, 范围 0~10 (0~0.5m/s), 默认6 (0.30m/s 同旧 POS_MAX); 巡逻 vx/vy 分轴限幅 |
| `pos_limit_x/y` | 位置环速度限幅 | uint8, 单位 0.05m/s, 范围 0~10 (0~0.5m/s), 默认6 (0.30m/s 同旧 POS_V_MAX); 位置环 PID 输出限幅 (v2.5.0) |

**航点总数语义** (v2.3.0 起由控制逻辑 `Inav_UpdateMax()` 运算): `bcn_max = wp_set`, `wp_max = bcn_max + launch_enable`。启用发车区则 `wp_max` 多 1 个航点, 坐标 = 起点(世界原点) + (`launch_off_x`, `launch_off_y`), 存于 `wp_abs[bcn_max]`。两值上电从 W25Q64 读回后覆盖, 覆盖原来的编译期宏 `BCN_MAX/WP_MAX` (已废弃)。

### 字库 (menu_font.c/h)
- 97 字 (索引 0~96); **数组顺序必须与 menu_font.h 枚举完全一致**。
- 新增字: PCtoLCD2002 取模 32 字节 → menu_font.c 数组末尾追加 → menu_font.h 枚举末尾加索引。

## 六、W25Q64 掉电存储模块 (2026-08-08 新增)

### 硬件接线 (软件SPI, 板级扩展引脚无硬件SPI复用)
| W25Q64 模块 | 单片机 | 说明 |
|---|---|---|
| CLK | P06_2 | SCK |
| DI  | P06_3 | MOSI (模块数据输入) |
| DO  | P06_4 | MISO (模块数据输出) |
| CS  | P06_5 | 片选 (驱动内手动控制) |
| VCC | 3.3V  | 固定 3.3V 供电 |
| GND | GND   | 共地 |

### 驱动设计要点
- 库 `soft_spi` 的 CS 是**每字节自动拉低/拉高** → 对 W25Q 致命 (页编程/擦除/读要求整条命令保持 CS 低)
- 解法: `soft_spi_init` 的 cs_pin 传 `SOFT_SPI_PIN_NULL`, CS 由驱动内 `gpio_low/high(W25Q64_CS_PIN)` 手动控制
- SPI Mode 3 (CPOL=1 空闲高, CPHA=1 第二边沿采样), `W25Q64_SOFT_SPI_DELAY=5`
- API (11 个): init / read_id / sector_erase / block_erase / chip_erase / page_write / write(自动跨页) / read / power_down / wake_up

### 存储分区 (v1.4.4, 类 STM32 内部flash区域划分, 人为划分便于管理)
```
Region 1 @ 0x000000 (扇区0): 惯导地图数据 — 航点地图
    格式: [1字节数量][数量×8字节坐标], 最多 FLASH_WP_MAX=9 个航点, 有多少航点记录多少
    坐标 flash_wp_t = {float x, float y} (米, 与惯导 pt_t 同布局)
Region 2 @ 0x001000 (扇区1): 设置参数 — 航点数量 + 发车区设置 + 惯导/位置环速度限幅
    格式: 12字节 flash_settings_t { magic=0x5A, wp_set, launch_enable, _pad, launch_off_x, launch_off_y, spd_limit_x, spd_limit_y, pos_limit_x, pos_limit_y }
```
- 写入须先擦除整扇区 (4KB), 接口: `FlashStore_Save/LoadSettings`、`Save/LoadWaypoints`、`ClearAll` (两扇区全擦)
- **上电加载链路**: init.c → `FlashStore_LoadSettings` → 覆盖菜单全局 (`wp_set`/`launch_enable`/`launch_off_x/y`/`spd_limit_x/y`/`pos_limit_x/y`) → `Inav_LoadMap()` 读 Region1 → 设 `bcn_max/wp_max` + 重建导航航点 (含发车区航点)
- 发车区航点**不存** Region1 (它由 Region2 的偏移实时算出), 地图区只存用户录制的航点
- `W25Q64_Persist_Test()` (test.c) 已注释: 存储模块接管后 0x000000 现为地图区, 旧测试读它会误报

### 验证结果 (2026-08-08)
- 初始化: `init OK, ID=0xEF4017` (W25Q64 识别正确)
- 通路测试: 擦扇区0 → 写 256 字节递增 → 读回比对 PASS
- **掉电持久化: 写 "Hello W25Q64!" → 断电 → 重启读回 `P-READ PASS! "Hello W25Q64!" survived power-off`** → 掉电不丢数据确认
- 测试入口: `W25Q64_Persist_Test()` (test.c), 宏 `W25Q64_PERSIST_WRITE` 切写/读; 已验证后当前为 0 (读模式), 每次上电打一行 `P-READ PASS`, 无害
- 测试期间 LoRa 调试打印全部暂注释 (周期性 `LORA:` + 状态变化 + init), 避免干扰串口判断

### 后续用途
菜单运行时配置 (`wp_set` / `launch_enable` / `launch_off_x/y` / `spd_limit_x/y` / `pos_limit_x/y`) 掉电持久化 → **v1.4.4/v2.4.0/v2.5.0 已接入** (Region2 存储, 上电加载回菜单全局, 巡逻/位置环运行时读取限幅)。

### 下地实测定案 (2026-08-09, 磁力计校准就此收尾)
```
抓包: 8.3s × 20ms = 415行 GRND 数据 (遥控打断诊断, 无线串口 vofa 采集)
检测到 11 个 duty 急变事件 (巡逻自身加减速 + 遥控操作):
  事件1  411665ms  Δduty=291  Δfused=2.3°  回正τ=1.34s   Δmag=434
  事件3  414226ms  Δduty=300  Δfused=0.9°  回正τ=0.08s   Δmag=628
  事件8  417487ms  Δduty=290  Δfused=2.9°  回正τ=0.38s   Δmag=618
  事件10 418827ms  Δduty=156  Δfused=1.8°  回正τ=0.50s   Δmag=379
最严重: Δfused=2.9° 回正τ=0.38s Δmag=618counts (≈10.2°航向等效, 半径3450)
```
**结论 (磁力计校准定案)**:
- 磁力计**确实被 EM 拉偏**: 急加减速瞬态 mag 最多被拉偏 618 counts ≈ 10.2° (基线噪声仅 ±50)。0.3m/s 巡逻约 30% duty 就有此幅度 → EM 干扰真实存在且不小。
- **但融合把污染压住了**: `fused_yaw` 全程最大只歪 2.9°, 回正 τ=0.38s (<0.4s)。角度环 98% 陀螺权重 + 磁力计仅 2% (时间常数≈1s) → EM 瞬态只漏进 <3°。
- **巡逻自身加减速 + 遥控满油门打断 (0.3m/s 限幅) 实测均无严重歪头**, 无影响 → **架构可用, 无需运动门控, 无需动态权重补偿**。
- **⚠️ 更高速度存疑**: EM 拉偏幅度随电流/duty 近似线性放大。0.3m/s (30% duty) 已拉 618counts≈10°, 若未来提速 (如满 duty 1000 ≈ 3.3×电流) 外推拉偏可达 20-30°。当前限速 0.3m/s 下实测无碍; 提速后需重测。若出现"歪头慢回正(≈1s级)", 预设方案 = **占空比突变时信任突变前的磁力计数据 (冻结/降权)**。

## 八·五、下地惯导实测 (2026-08-09 首次, 磁力计实时基准架构)

### 操作流程 (与菜单记录/发车全链路一致)
```
上电 → 清除历史数据 → 设置航点数量 → 记录航点(带磁力计, 车头朝航点推车) →
菜单发车(Inav_Launch: MagYaw_Reset 车头=世界0°) → 巡逻去航点 → 肉眼观察车头
```
关键前提: 发车时车头物理朝向须与上电时一致 (记录基准 = 上电 MagYaw_Reset, 发车重新归零 → 不一致则地图整体旋转)。

### 实测现象 (三观察点)
```
1. 惯导航向: 车头歪了几度后在该位置稳定, 不继续歪下去 (稳态小偏移, 无累积漂移)
2. 遥控直走加减速: 车头被"扯歪"更明显 (瞬态偏移增大)
3. 遥控停车到某位置: 角度又回正 → 判断为动态干扰, 非磁力计绝对基准错误
```

### 分析 (已由抓包实测证实)
- **惯导稳态歪几度但稳定**: 磁力计绝对基准在持续拉回 (无累积), 但有稳态角度差修不过去 — 来源可能: 磁力计安装角度残差 / 软铁修正残余 / 修正权重不足。
- **加减速瞬态扯歪 + 停车回正**: 符合**动态 EM 干扰**特征 — 电机加减速大电流磁场变化扭曲磁力计读数, 电流归零后磁场恢复 → 角度回正。抓包实测证实: 瞬态 mag 拉偏最大 618counts≈10°, 但 `fused_yaw` 仅歪 2.9° 且 <0.4s 回正。
- 陀螺欠积分 (+289.7°/360°) 在磁力计修正下未造成可见累积漂移 (观察点1证明)。

### 最终结论 (2026-08-09 定案, 见第七章"下地实测定案")
```
架构可用: 0.3m/s 限速下 巡逻加减速 + 遥控满油门打断 均无严重歪头, 无需运动门控/动态补偿
更高速度存疑: EM 拉偏随 duty 近似线性 (30%→618counts), 提速后需重测
备用方案 (若提速后歪头慢回正): 占空比突变时信任突变前的磁力计数据
```

## 十三、关键坑位提醒

1. **10kHz PWM**: zf_driver_pwm.c分频9u + PWM_DUTY_MAX=1000 (勿动)
2. **ISR禁printf**: 浮点printf会卡死10ms中断
3. **PID覆盖开环**: 测试开环PWM必须先 Motor_Enable_PID(0)
4. **pos_error是static**: App层写入用 SetPositionError()
5. **编码**: project/为UTF-8, libraries/大部分GBK (改注释注意)
6. **遥控器50ms必发帧**: 不能只靠"收不到帧"判丢信标, 必须加空闲判定
7. **上电误锁完赛**: 完赛触发必须有首帧保险(0xff) + mission_armed 门控, 否则上电即锁
8. **位置环满推限速**: 满推速度 = 摇杆缩放K × 位置环Kp, 要调快改 APP_STICK_K 或 POS_V_MAX
9. **菜单整页重绘循环边界与行数同步**: 主菜单 4 行 (v2.5.0 加位置环限幅) `MAIN_ROWS[4]`/`i<4`/`%4`, INR 二级 5 行 (v2.4.0 加速度限幅) `INR_ROWS[5]`/`i<5`/`%5` — 行数组/重绘循环/KEY_1 取模三处必须一致 (曾 i<2 漏画第三行→黑屏; 加行后勿只改取模不改重绘)
10. **字库索引顺序**: menu_font.c 数组与 menu_font.h 枚举顺序必须完全一致 (索引即字), 新增字先取模占位再补
11. **menu_show_text 传指针**: 收 `menu_text_t*`, MT() 返回结构体值, 须先存局部变量再取 `&` 传入
12. **W25Q64 软SPI的CS**: 库 soft_spi 每字节自动拉低/拉高 CS, 对 W25Q 致命 (页编程/擦除/读需整条命令保持 CS 低) → soft_spi_init 传 `SOFT_SPI_PIN_NULL`, CS 由驱动手动控制
13. **状态机缓冲区必须 static**: 跨多次主循环调用的状态机, 局部数组每次进入重新分配未初始化 → 比对出假 FAIL (曾把 PASS 误判成 FAIL @0x0038)
14. **持久化读验证前禁 W25Q64_Test()**: 它会先擦扇区0, 把要验证的持久化数据冲掉
15. **printf 消息用 ASCII**: 中文在串口终端显示乱码 (曾把"掉电不丢数据"打成乱码), 测试消息统一英文
16. **存储分区须扇区对齐**: Region1 @0x000000 / Region2 @0x001000 (各占一个 4KB 扇区), 写前整扇区擦除, 不能跨扇区写设置
17. **航点上限是运行时变量**: 数组按物理上限 `FLASH_WP_MAX=9` 开 (wp_abs 为 9+1 留发车区), 循环一律用 `bcn_max/wp_max` 而非原宏 `BCN_MAX/WP_MAX` (已废弃)
18. **发车区航点不存地图区**: 它由 Region2 的 `launch_off_x/y` 实时算出 (`wp_abs[bcn_max]`), 上电重建, 别往 Region1 多存
19. **W25Q64 写入阻塞主循环**: 擦扇区轮询 WIP 期间主循环停转, 但硬件中断照常 (10ms ISR 不受影响); 自动返回用独立节拍器 PIT_CH10 不受阻塞影响
20. **磁力计标定随安装位置变**: 硬铁/软铁对车架/线束/地面磁环境敏感, 换安装高度/位置后须重标 (旧2G值 X=-24325 在架高后实测已失效, 重标为 -145/-521)
21. **发车必须 MagYaw_Reset()**: 它同时对齐 mag_offset 与融合状态 mag_fy (只改 offset 会留残余差, 发车瞬间世界系有残差); 记录/导航/控制三处 yaw 必须同一基准 (fused_yaw), 否则地图会整体旋转
22. **磁力计绝对基准≠无累积误差**: fused_yaw 每20ms拉回绝对值, 但软铁修正残余是**角度的函数** (非固定偏移), 发车归零只能消固定偏移 → 位置误差会随转角累积, 下地实测直接观察此项
